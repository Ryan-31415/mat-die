## 병목과 변경

고정 관측 120개 투사체를 250회 판단한 Node 샘플 프로파일의 상위 자기 시간 샘플은 `prepareAIFrame` 421, 이동 `evaluate` 221, GC 127, 공통 충돌 함수 42, 화살 예측 10이었다. 짧은 샘플 프로파일이므로 정밀한 함수별 시간 비율로 보지 않는다.

1. `world.ts`: 투사체마다 매 예측 스텝에 수행하던 플레이어 전체 복사 2회를 충돌용 사각형 1개 생성으로 대체했다.
2. `archerShot.ts`: 매 스텝의 상대 전체 복사를 좌표 복사로 줄였다. 방패와 상태는 같은 관측 상대에서 읽는다. 코일 대체 목록은 화살 예측 호출 안에서 한 번만 필터링한다. 판단 간 캐시는 없다.
3. 추가 수정 `projectile.ts`: swept collision의 중첩 배열 3개 생성을 없앴다. x축 다음 y축의 산술·비교·조기 반환 순서를 유지했다. 공유 엔진도 사용하는 함수이므로 원본 알고리즘과 독립 대조 테스트를 추가했다.

전술 가중치·예측 길이·관측 권한·난이도·난수 호출을 바꾸지 않았다. 회피나 사격 예측을 생략하지 않았다.

## CPU 측정

Node v22.18.0, Intel Core i5-13420H, Windows 10.0.26200, 전원 Balanced. 동일 프로세스의 단일 워커에서 실제 엔진을 진행하지 않고 같은 완전 난이도 관측을 반복했다. 진단 계수는 별도 빌드로 수집해 시간 측정에서 제외했다.

최종 측정은 각 조건·버전마다 준비 160회, 측정 240회, 3반복이다. 변경 전·후·과거 버전을 16회 블록으로 교차 실행하고 순서를 회전했다. 다른 검증 명령은 최종 측정과 겹치지 않게 실행했다. 표는 각 지표의 3반복 중앙값(ms), 변화율은 중앙값끼리 비교한 값이다.

| 투사체 | 평균 전 → 후 | p95 전 → 후 | p99 전 → 후 | p95 변화 | 궁수 개선 전 대비 p95 |
|---|---|---|---|---|---|
| 0 | 0.267 → 0.229 | 0.571 → 0.459 | 0.857 → 0.684 | -19.6% | +3.9% |
| 20 | 1.778 → 1.422 | 2.594 → 2.141 | 3.078 → 2.438 | -17.5% | +10.5% |
| 60 | 4.392 → 3.249 | 5.989 → 4.511 | 6.965 → 5.029 | -24.7% | +7.0% |
| 120 | 9.620 → 6.848 | 12.548 → 9.424 | 13.554 → 10.108 | -24.9% | +5.9% |

프로파일과 벤치마크 2회 합계 **81.9초**. 첫 측정은 긴 버전별 블록을 사용했고 부하 변동이 컸다. 첫 후보에서 20개 조건의 허용 기준을 만족하지 못해 추가 수정 1회를 적용했다. 첫 측정과 최종 측정은 블록 방식이 달라 추가 수정 하나의 기여도를 직접 산출하지 않는다. 최종 표는 최종 실행 내부의 동결 기준선 대조만 사용한다. 반복별 원자료와 짝별 p95 비율 중앙값도 `aiCpuStage2Results.json`에 보존했다.

고부하 10% 감소 및 다른 조건 5% 초과 악화 없음은 이 고정 관측 패널에서 통과했다. 과거 대비 모든 조건 +10% 이내 목표는 20개 조건 때문에 일부 미달이다. OS 부하·주파수·GC에 따른 변동은 남으며, 실제 게임 프레임 성능이나 일반적인 성능 우월성을 입증한 결과는 아니다. 메모리 할당 바이트는 측정하지 않았다.

## 동일성 및 검사

- 10캐릭터 × 5맵 × 5난이도 × 2상태 × 3관측 전이 = **1,500회**에서 전체 반환 런타임이 정확히 같았다. 입력, AI 메모리, 관측/입력 대기열, 학습 상태, 난수 상태를 포함한다. 원본 관측과 이전 런타임의 비변이성도 검사했다. 게임 엔진이나 물리 세계를 진행하지 않았다.
- 고정 CPU 장면의 변경 전·후 이동 후보 평가 6회, 상세 화살 예측 1회로 동일했다. 0/20/60/120개 조건의 충돌 검사도 각각 285/1,102/2,736/5,187회로 동일했다. 계수 빌드 반환값도 비계수 기준선과 같았다.
- 충돌 함수 원본 대조: 유한 좌표 2,000개, 정지축·역방향·경계·Infinity·NaN 조합 243개 통과.
- 관련 단위 테스트 **9파일 160개 통과**: 화살, 전술 판단, 난이도, 관측, 위치 선정, 매치업, 학습, 투사체 및 충돌 동일성.
- 앱 타입 검사, 변경 TypeScript 파일 ESLint, 프로덕션 빌드 통과. 빌드는 기존 Browserslist 데이터와 청크 크기 경고를 출력했다.
- 전투 시뮬레이션이 포함되는 통합·평가 테스트와 전체 테스트는 실행하지 않았다. 브라우저 플레이·렌더링·전체 프레임 CPU는 미검증이다. 고정 장면 동일성은 모든 가능한 상태의 증명은 아니다.

## 도구와 재현 자료

`aiCpu.mjs`는 esbuild(기존 설치)를 사용해 같은 설정으로 동결/후보 빌드를 만든다. 계수 삽입은 별도 빌드에만 적용되며 운영 코드에 계수용 분기나 할당을 추가하지 않는다.

```powershell
# 구현 전 상태에서 한 번 실행: 기존 기준선 덮어쓰기 금지
node src/test/aiCpu.mjs freeze
node src/test/aiCpu.mjs profile
# 구현 후 고정 관측 동일성, 실제 경기 없음
node src/test/aiCpu.mjs check
# 단독 실행: 다른 검사/빌드와 병행하지 않음
node src/test/aiCpu.mjs bench
```

로컬 상세 자료는 Git 제외 경로 `docs/ai-runs/cpu-stage2`에 있다. `before.cjs`/메타데이터는 시작 시점 기준선, `before-counted.cjs`는 계수판, `profile.json`은 샘플 프로파일, `benchmark-1.json`/`benchmark-2.json`은 원자료, `parity.json`은 동일성 결과, `budget.json`은 실행 예산이다. 과거 비교는 기존 `docs/ai-runs/archer-stage1-baseline/baseline.cjs`를 사용했다. 저장소에 포함되는 결과 파일은 `aiCpuStage2Results.json`이며 각 번들 해시도 기록한다. 상세 번들 없는 새 체크아웃에서는 먼저 해당 기준선 소스를 마련하고 동결해야 한다.

도구는 기존 기준선을 덮어쓰지 않고, 프로파일 1회·벤치마크 최대 2회·누적 300초를 제한한다. 이번 세션의 측정 예산 파일을 삭제하거나 우회하지 않았다.

## 권고

현재 변경을 검토 대상으로 유지한다. 고정 관측 전투 판단을 보존하면서 현재 푸시 버전 대비 주요 CPU 목표를 달성했다. 궁수 작업 1의 전술 채택 여부까지 확정하는 결과는 아니며, 과거 대비 20개 조건 +10.5%와 실제 플레이 성능은 남은 제한이다. 추가 최적화·작업 3–5·커밋·푸시는 진행하지 않고 사용자 검토를 기다린다.
